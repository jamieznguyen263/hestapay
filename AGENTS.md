# HestaPay AGENTS.md

## Project identity

This repository is for **HestaPay**, not StoaHub.

HestaPay is a payment software and orchestration layer for local businesses.

Target industries:
- restaurants
- nail salons
- retail
- home services

HestaPay is **not**:
- a bank
- a payment processor
- an acquirer
- a payment infrastructure provider

HestaPay integrates with trusted payment infrastructure partners.

## Current objective

The current objective is to build a **high-fidelity internal preview** of HestaPay.

This repository should no longer be treated as placeholder-only marketing art.
The goal is to produce polished product screens and marketing pages that feel
close to a real product experience for internal review, stakeholder feedback,
founder review, and pre-launch storytelling.

These screens are still not live production app features, but they should be
complete enough to review as if they were part of a real product system.

## Internal preview brand-content rules

For internal preview work, fictional brand content is allowed.

Allowed:
- fictional testimonials
- fictional customer logos
- fictional merchant names
- fictional operator names and titles
- fictional partner placeholders
- fictional trust/proof layouts for visual review

Requirements:
- keep them clearly internal-preview in intent
- do not imitate a real company too closely
- prefer reusable fictional names and marks across the repo
- replace or verify before any public release

Still not allowed:
- fake compliance badges
- fake PCI/SOC claims
- unsupported public marketing claims presented as verified fact

## Internal preview data rules

For internal preview work, realistic-looking UI data is allowed.

Allowed:
- realistic transaction amounts
- realistic totals, counts, and rates
- realistic dashboard cards and table rows
- realistic checkout, QR, payment-link, refund, tip, and reporting states
- realistic internal product copy inside mock screens

Still not allowed:
- fake compliance trust proof
- unsupported public marketing claims

If a screen is being prepared for public release later, review all numbers and
claims again before treating them as public-facing.
